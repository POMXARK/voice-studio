# VoiceStudio — программа для генерации озвучки

Локальный веб-интерфейс (stdlib Python, без зависимостей): редактирование реплик, выбор модели и образца голоса, генерация, оценка качества, установка в игру.

## Запуск (Windows)
```
cd C:\voice\studio
python server.py          # затем http://127.0.0.1:8777
```
Настройки — `config.json` (папка проекта `work`, папка игры `game_dir`, python с Whisper `score_python`, `campplus.onnx` для тембра, порт). Проект — это папка `work` (`C:\voice\cap`): `texts.tsv` (русский текст), `texts_<язык>.tsv`, `<язык>_wav/`, `dub_wav/`, `dub_wem/`. Состояние студии — `studio.json`, дубли — `studio/takes/<реплика>/`, задачи — `studio/jobs/<id>/` (`job.log` — живой вывод).
Уже сделанный набор (`best/`, `bad.txt`) переносится в студию один раз: `python import_cap.py C:\voice\cap`.

## Что умеет
| Функция | Как |
|---|---|
| Список реплик | текст, оригинальные тексты языков, статус (нет / TTS / дубль другого автора), фильтры, поиск |
| Сравнение трёх версий | при выборе реплики справа карточка: субтитр игры (русский) + три колонки — оригинал, моя (Qwen), другого автора (мод); у каждой ▶ и расшифровка Whisper (оригинал — ja, моя — что услышал Whisper, другого — ru), у моей ещё score/WER/тембр; «Все по очереди» играет оригинал → моя → другого. Зелёная рамка — версия, которая пойдёт в игру |
| Пометки | 👎 «плохая» (в игру не ставится, пока не заменена), 🔁 «на перегенерацию», «заменить на версию другого автора» — на реплике, на выбранных и клавишами; фильтры по пометкам; «⚙ Перегенерировать помеченные» ставит их в очередь и снимает 🔁 |
| Клавиши | ↑↓ реплика · 1 оригинал · 2 моя · 3 другого · 0 все по очереди · B плохая · R перегенерация · D заменить дублем |
| Прослушивание | ▶ оригинала (каждый язык), дубля другого автора, нашей озвучки |
| Правка текста | поле «Русский текст» → «сохранить» → сгенерировать заново; «вернуть исходный» |
| Модель | умолчание проекта и своя на реплику; список в `models.json` (Qwen3-TTS 1.7B/0.6B, CosyVoice 3), добавляется строкой |
| Откуда голос | оригинал игры (язык `ja`/другие `<язык>_wav`), русская озвучка другого автора, **свой wav-образец** (загрузка + расшифровка; пусто — Whisper) |
| Образец из нескольких реплик | имена через пробел → склейка до 20 с (больше тембрового материала) |
| Параметры | JSON поверх умолчаний модели (`temperature`, `top_p`, `top_k`, `repetition_penalty`, `seed`, `tail`, `non_streaming`) |
| Несколько дублей | «дублей N» — N генераций с разными seed; выбрать лучший |
| Оценка | Whisper-ru (WER, пропущенные слова в хвосте), длина к дублю другого автора, тембр (косинус CAM++), метка галлюцинаций; score > 0.5 — плохо |
| Установка | «Установить в игру»: выбранный дубль → `ru_cap\<имя>.wav`; «дубль другого автора» → `.wem` (старый файл того же имени убирается, `.wem` в `Dir` приоритетнее `.wav`) |
| Этапы от лёгкого к сложному | панель над списком, у каждого этапа счётчик и кнопки «всё» / «выбранные»: **① Генерация** (без проверок, самое быстрое) → **② Проверка** (Whisper + тембр + длина, только для созданных) → **③ Исправление** (плохие score>0,5: 3 новых дубля с другими seed/temperature/top_p, одна попытка на реплику) → **④ Выбор лучшего** (лучший дубль ≤0,5 → в игру; иначе версия другого автора, если есть; иначе помечается 👎). Запускать можно по отдельности в любое время |
| Автоконвейер | «🌙 Запустить автоконвейер» сам идёт по этапам 1→4, пока есть работа; этап берётся, когда нет работающих задач (пауза задачи держит конвейер); реплики, которые этап не смог взять (нет образца), повторно не берутся |
| Фоновая очередь | «🌙 Фоном: все без озвучки» ставит в очередь все реплики без озвучки; у каждой задачи полоса прогресса, `N/всего`, скорость (с/реплика) и оценка «осталось» |
| Пауза / продолжение | «⏸ пауза» (на задаче или «Пауза всё»): воркер доделывает текущую реплику и ждёт, модель остаётся в памяти — «▶ продолжить» стартует мгновенно. «стоп» убивает процесс; остановленную или оставшуюся после перезапуска студии/ПК задачу можно «▶ продолжить» — воркер пропускает уже сделанное (результаты лежат в `jobs/<id>/results.jsonl`) |
| Консоль | список задач и живой лог каждой |

## ⓪ Подготовка проекта (универсальная студия)

Студия не привязана к одной игре: подготовка сама вытаскивает голосовые записи и субтитры, потом можно запускать этапы ①–④.

Источники (адаптеры, `prep.py`):
- **Папка с записями** (`folder`) — `<имя>.wav/.wem/.ogg/.mp3/.flac` (можно во вложенных папках) + файл субтитров `имя<TAB>текст`; любая игра/проект.
- **Crimson Desert** (`crimson_paz`) — субтитры из групп PAZ (0022, rus), голоса из групп языков (ko, en, zh, fr, de, ja, pt, es; можно несколько через пробел).
- **Свой скрипт** — `script:путь.py` с функцией `collect(params, say)`, возвращающей список `{"name","text","voices":{язык:путь},"dub":путь}`.

Режимы образца голоса: язык оригинала (любой из найденных), «любой язык» (первый найденный, порядок задаётся списком), либо «на основе русской озвучки другого автора» (образец — его запись, если так проще). Конвертация: wem → vgmstream-cli, остальное → ffmpeg (пути в `config.json`: `tools`, `prep_python`).

«✅ Авто в игру» в шапке: готовые реплики сами попадают в папку игры раз в N секунд (по умолчанию 60) или когда накопилось K новых. Что уже установлено, записано в таблице `installed.json` (путь, размер, время): повторно ничего не копируется. В игру кладётся жёсткая ссылка, а не копия, если студия и игра на одном диске, — место не тратится. Плохие (🔴) не устанавливаются; кнопка «Установить в игру» ставит всё заново.

Кнопка «🔄 Перезапуск» в шапке перезапускает сервер: все идущие проходы (генерация, расшифровка, оценка) останавливаются и модели выгружаются из памяти. Задачу можно продолжить кнопкой «продолжить» — готовое пропускается. Воркеры, пережившие перезапуск по другой причине, видны в списке задач и останавливаются кнопкой «стоп».

У путей есть кнопка «📂 Обзор» (окно-проводник по папкам компьютера, где запущена студия); поля можно и просто вписать.

Для адаптера Crimson Desert в Python подготовки нужны `lz4` и `cryptography` (`python -m pip install lz4 cryptography`; в окружении cosyvoice на Windows уже установлены).

Для ~100 тыс. реплик список подгружается страницами: поиск и фильтры работают на сервере.

## Запуск в свободное время
`Start-VoiceStudio.bat` (рядом с `server.py`) запускает сервер и открывает браузер. Задачи переживают закрытие вкладки; при закрытии окна сервера процесс генерации умирает, но результаты сохранены — после нового запуска нажать «▶ Продолжить всё». Ночью/в простое: «Фоном: все без озвучки» → «Пауза всё», когда нужна видеокарта (игра), → «Продолжить всё», когда свободна.

## Своя модель
В `models.json` добавить запись. Встроенные адаптеры: `qwen3`, `cosyvoice3`. Свой — `"adapter": "script:C:\\путь\\my_tts.py"`, файл с функцией `load(cfg)`, возвращающей `synth(text, ref_wav, ref_text, params) -> (samples, sample_rate)`. Поле `python` — интерпретатор окружения модели.

## Ограничения
- Сервер слушает только 127.0.0.1; доступа без авторизации нет, наружу его не открывать.
- Пауза держит модель в видеопамяти (нужна для мгновенного продолжения); чтобы освободить её под игру — «стоп», потом «продолжить» (загрузка модели ~десятки секунд).
- Одна задача = один процесс с загрузкой модели (десятки секунд); пачка реплик одной модели идёт одной задачей.
- Тембр кросс-языкового клонирования ограничен (косинус ≤ ~0,78); для коротких реплик с вздохом лучше склейка образцов или свой образец.

## Потоки генерации и расшифровка образцов

- **Потоки** (селектор в шапке): сколько копий модели генерируют одновременно. «Авто» добавляет поток, пока GPU загружен меньше 70% и хватает видеопамяти/ОЗУ, и убавляет при нехватке; число 1–4 — вручную. Потоки берут реплики из общей очереди (папка `claims/` задачи). На 16 ГБ видеопамяти Qwen3-TTS + Whisper два потока не вмещают — скорость падает, поэтому по умолчанию 1.
- **⓪ Образцы**: Whisper расшифровывает оригинальные образцы один раз (8 параллельных запросов, ≈8 реплик/с) в `texts_<язык>.tsv`; генерация берёт текст оттуда и не грузит Whisper. На время расшифровки генерация останавливается и потом продолжается сама.
- **Модели в памяти**: в шапке и на карточке задачи видно, какая модель загружена и сколько копий работает («Qwen3-TTS ×2»). Объём видеопамяти берётся из `nvidia-smi` (всего на GPU), а не по процессам: на Windows `nvidia-smi` по процессам отдаёт N/A, а дельты разных воркеров при одновременном запуске перекрываются. Пока процесс грузит модель, статус «загружается модель».

## «Странная реплика» — выборочная проверка вместо полной

Услышали в игре неестественную реплику — нажмите горячую клавишу: реплики, которые игра запрашивала за последние 5 минут (из `VoiceLayer.lines.tsv`, только именованные), получают отметку «на проверку» и записываются в `suspect.log` (рядом со `studio.json`: строки `время<TAB>live<TAB>имя`, заголовок окна `# …`). Если игра не запущена, окно берётся от последней записи лога.
- **В игре**: `suspect_hotkey.ps1` (запуск в сессии пользователя: `powershell -ExecutionPolicy Bypass -File C:\voice\studio\suspect_hotkey.ps1`), клавиша **Ctrl+Alt+F9**, подтверждающий звук.
- **На странице студии**: кнопка «⚠ Странно (5 мин)» или клавиша **F8**.
- **Дальше**: фильтр «⚠ на проверку (странные)» → «выбрать видимые» → «Оценить». После оценки отметка снимается сама. API: `POST /api/suspect {minutes, name?, clear?}` (`name` — окно по времени генерации этой реплики, `clear` — снять все отметки).

## Быстрый детектор искажённых дублей

Спектральные признаки (центроид, плоскостность, rolloff, ВЧ, ZCR) на отмеченном «плохом» дубле не отличались от нормы. Надёжно работает длительность к тексту: ожидаемая = 0,5 + 0,075·символов; ≥3× — речь без остановки (runaway, нет EOS), <0,4× — обрыв. Плюс numpy-проверки: клиппинг >0,2 %, пик <0,02, плоский спектр (шум). Стоит миллисекунды. Воркер пишет `quick` в take, ingest ставит `suspect` и дописывает `suspect.log` (источник `auto`). Скан готовых: `POST /api/suspect {"scan":true}`. Фильтр «странные» показывает и ручные, и авто. На норме (5466 дублей) срабатывает ≈0,6 %.

## Расшифровка Whisper (образцы и оценка)

Реплики короткие (1–10 с), энкодер Whisper всегда считает окно 30 с. `asr_batch.py` собирает в один пакет окна **разных** реплик (штатный `transcribe` и `BatchedInferencePipeline` пакетируют только куски одной длинной записи), сортирует их по длине и декодирует пакетом.

| вариант (160 японских образцов, RTX 5080) | мс на реплику | энкодер, мс |
|---|---|---|
| faster-whisper (CTranslate2 4.8.3), 8 потоков — было | 293 | 148 |
| CTranslate2, свой пакет 16 | 230 | 148 |
| **transformers 5.15.1 + torch 2.11 cu128, SDPA fp16, пакет 16** | **84** | **34** |
| то же, пакет 32 | 116 | 34 |

- CTranslate2 4.8 на Blackwell (sm_120) медленный: энкодер ×4 к torch; `int8_float16` падает (`CUBLAS_STATUS_NOT_SUPPORTED`). Поэтому движок по умолчанию — `hf` (переменная `STUDIO_ASR=ct2` вернёт старый).
- Пакет 32 медленнее 16: декодер ждёт самый длинный текст пакета.
- Тексты: 141 из 159 совпали с прежней расшифровкой буква в букву, остальные — варианты записи (каной/иероглифами), часть точнее (日当 вместо 日東).
- large-v3-turbo через CTranslate2: 159 мс против 230, но совпало только 130/160, ошибки на японском (キリを抜くな) — оставлен large-v3 (`STUDIO_ASR_MODEL`).
- large-v3-turbo через transformers, пакет 32: 50 мс/реплику (энкодер тот же 36 мс, выигрыш в декодере на 4 слоя), но японский хуже (キリを抜くな вместо 気を抜くな) — для образцов не взят.
- Оценка на `fq5`: расшифровка и WER те же, косинус тембра CAM++ сдвинулся на 0,04–0,08 (другие torchaudio/onnxruntime; wav читается через soundfile — `torchaudio.load` 2.9+ требует torchcodec).
- Расшифровка и оценка запускаются питоном `asr_python` (по умолчанию venv быстрых режимов `C:\voice\fq5`, туда ставится и `onnxruntime` для тембра CAM++).

## Режимы генерации (переключатель «режим» в шапке)

| режим | как | 16 реплик, генерация | заметки |
|---|---|---|---|
| обычный | штатный qwen_tts, по одной | 107,7 с | эталон |
| пакет | штатный qwen_tts, список текстов за один вызов (4/8/16) | 35,2 с (×3) | seed общий на пакет, реплики с разными параметрами идут отдельными пакетами; упавший пакет повторяется по одной |
| быстрый | faster-qwen3-tts 0.3.1: те же веса, статический KV-кэш + CUDA graphs | 22,6 с (×4,8, вкл. ~10 с прогрева) | звук не побитово равен штатному (другие ядра bf16), длительности те же |
| быстрый пакет | CUDA graphs + пакет: форк [POMXARK/faster-qwen3-tts@batched](https://github.com/POMXARK/faster-qwen3-tts/tree/batched) = 0.5.4 + PR #150 (yu45020, MIT, в апстрим не слит) | 12.0 с (×9 к обычному; пакет 8 после прогрева ≈ 0.3 с/реплику) | граф на каждый размер пакета снимается при первом пакете (~8 с); без форка воркер пишет предупреждение и работает по одной |

Замер: RTX 5080, Qwen3-TTS 1.7B Base, одни и те же 16 реплик (`C:\voice\bench\<режим>`), один поток.
Смена режима перезапускает потоки идущей генерации (взятые, но не сделанные реплики возвращаются в очередь). Режим и размер пакета — в `threads.json`, воркер получает их через `STUDIO_ENGINE`/`STUDIO_BATCH`.

Быстрые режимы живут в своём venv `C:\voice\fq5` (`install_fast.bat`, путь можно задать `fast_python` в config.json). Тупики при установке:
- faster-qwen3-tts 0.5.x + qwen-tts-hf: с transformers 5.22 модель не грузится (`upsample` без setter), с 5.2 — нет `validate_layer_type`, с 5.12 грузится, но **ни одна реплика не заканчивается** (нет EOS) — звук до потолка токенов.
- faster-qwen3-tts 0.5.4 со штатным qwen-tts 0.1.1 + transformers 4.57.3 падает (`StaticLayer.lazy_initialization`).
- Работает: transformers **5.15.1** (ровно то, что требует pyproject 0.5.4) + qwen-tts-hf 0.1.1.post1 + форк `batched` (`--no-deps`); одиночный «быстрый» на нём — 20,3 с на те же 16 реплик. Прежний вариант (qwen-tts 0.1.1 + transformers 4.57.3 + faster-qwen3-tts 0.3.1, venv `C:\voice\fq`) тоже работает, но без пакета.
- pip из ветки чужого форка PR блокировался проверкой прав; поэтому ветка PR #150 (лежит прямо поверх апстрим `main`, без конфликтов) опубликована в своём форке и ставится оттуда.
